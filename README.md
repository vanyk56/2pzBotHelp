# 2pzBotHelp — бот заявок в клан с ИИ-ассистентом

Discord-бот для приёма заявок в клан 2pz:

- **Кнопка «Подать тикет»** закреплена в канале заявок (`/panel`). Нажатие открывает анкету из 5 полей.
- **Приватный канал заявки** создаётся в категории «заявка в клан, тикеты». Видят его только игрок и модерация.
- **Анкета** уходит в канал с пингом ролей модерации и кнопками «Принять», «Взять на рассмотрение», «Вызвать на обзвон», «Отклонить».
- **ИИ-ассистент** (модель через River API) приветствует игрока, говорит, что в скором времени его вызовут на обзвон, и отвечает на вопросы. Он помнит последние N сообщений тикета и знает анкету игрока.
- **Neon (Postgres)** хранит все заявки и всю переписку. Эти данные пригодятся для дообучения модели.

## Структура

```
config/
  form.json            — поля анкеты (подписи, тип поля, лимиты). Можно править без кода
  system-prompt.md     — характер, знания о клане и правила ассистента. Можно править без кода
src/
  index.js             — точка входа, подключение к Discord, регистрация команд
  tickets.js           — панель, создание тикетов, кнопки модерации, чат с ассистентом
  assistant.js         — сборка контекста для модели (промпт + анкета + история)
  ai.js                — клиент OpenAI-совместимого API
  db.js                — схема и запросы к Neon
  form.js              — сборка модалки из form.json
  config.js            — переменные окружения
test/                  — unit-тесты (npm test)
```

## 1. Discord-приложение

1. Откройте [discord.com/developers/applications](https://discord.com/developers/applications) → **New Application**.
2. Вкладка **Bot** → **Reset Token** → скопируйте токен в `DISCORD_TOKEN`.
3. В той же вкладке включите **Message Content Intent**. Без него бот не увидит, что пишет игрок.
4. **OAuth2 → URL Generator**: scope `bot` и `applications.commands`. Права бота:
   - View Channels, Send Messages, Read Message History, Embed Links
   - Manage Channels (создаёт каналы заявок), Manage Messages (закрепляет и удаляет старые панели)
5. Откройте сгенерированную ссылку и добавьте бота на сервер.
6. Роль бота должна стоять **выше** ролей модерации, иначе он не сможет выдать им доступ к каналу заявки.

ID берутся из Discord: **Настройки → Расширенные → Режим разработчика**, затем ПКМ по серверу, каналу, категории или роли → «Копировать ID».

## 2. Neon

1. Создайте проект на [neon.com](https://neon.com).
2. Скопируйте строку подключения (вариант *Pooled connection* тоже подходит) в `DATABASE_URL`.
3. Таблицы создаются сами при первом запуске (`tickets`, `ticket_messages`).

## 3. Переменные окружения

```bash
cp .env.example .env
```

Заполните `.env`. Файл не коммитится (есть в `.gitignore`). Токены нигде в репозитории хранить не нужно: на хостинге задайте их как переменные окружения.

| Переменная | Что это |
|---|---|
| `DISCORD_TOKEN` | Токен бота |
| `GUILD_ID` | ID сервера 2pz – community |
| `PANEL_CHANNEL_ID` | Канал, где закреплена кнопка подачи |
| `TICKET_CATEGORY_ID` | Категория «заявка в клан, тикеты» |
| `STAFF_ROLE_IDS` | Роли модерации через запятую (Owner, Co-owner, Moderator) |
| `VOICE_CHANNEL_ID` | Голосовой канал обзвона `•CHECKING`. Необязательно |
| `DATABASE_URL` | Строка подключения Neon |
| `RIVER_API_KEY` | Ключ River API |
| `RIVER_BASE_URL` | По умолчанию `https://api.river.ai/v1` |
| `AI_MODEL` | По умолчанию `zai-org/GLM-5.3-Flash` |
| `AI_CONTEXT_MESSAGES` | Сколько последних сообщений тикета уходит модели как память. По умолчанию 30 |
| `AI_MAX_TOKENS` | Лимит длины ответа. По умолчанию 700 |

## 4. Запуск

```bash
npm install
npm test        # unit-тесты
npm start       # запуск бота
```

Требуется Node.js 22.9 или новее.

После запуска в канале заявок выполните `/panel`. Бот опубликует сообщение с кнопкой, закрепит его и удалит прошлую панель, если она была.

## Команды

- `/panel` — опубликовать и закрепить кнопку подачи (только модерация)
- `/close` — закрыть тикет: статус становится «закрыт», канал удаляется через 10 секунд. История остаётся в Neon (только модерация)

Один игрок может иметь только одну незакрытую заявку. Это ограничение есть и в коде, и в базе (частичный уникальный индекс).

## Как настроить анкету и поведение ассистента

- **Поля анкеты** — `config/form.json`. Лимит Discord: до 5 полей, подпись до 45 символов. Поле `style: "paragraph"` даёт многострочный ввод. После правки перезапустите бота, а `/panel` опубликуйте заново.
- **Знания и характер ассистента** — `config/system-prompt.md`. Сюда попадают правила клана, требования, FAQ и ограничения. Чем полнее этот файл, тем точнее ответы. Модель получает его целиком при каждом ответе.
- Ассистент видит анкету и статус конкретного игрока, поэтому отвечает по его данным.

## Хранение данных и дообучение

- `tickets` — заявки: игрок, ник, ответы анкеты (JSON), статус, кто принял решение.
- `ticket_messages` — переписка: роль (`user` — игрок, `assistant` — бот, `staff` — модератор, `system` — смена статуса), автор, текст, время.

Для будущего дообучения можно выгрузить диалоги из Neon, например:

```sql
SELECT t.id AS ticket_id, t.status, m.role, m.author_name, m.content, m.created_at
FROM ticket_messages m
JOIN tickets t ON t.id = m.ticket_id
ORDER BY t.id, m.id;
```

Потом эти данные нужно привести к формату, который требует выбранная платформа дообучения (обычно JSONL с парами «вопрос — ответ»). Хорошие примеры — ответы, после которых игрок получил решение без уточнений. Перед использованием данные стоит проверить вручную.

## Что проверено и что нет

- Unit-тесты: сборка модалки и лимиты анкеты, сборка запроса к модели и разбор ответа, сборка контекста, имена каналов, разбиение длинных сообщений.
- Не проверено end-to-end: подключение к Discord, Neon и River API. Для этого нужны реальные токены и доступ к этим сервисам с вашей машины или хостинга.
- Контракт River API предполагается OpenAI-совместимым (`POST {RIVER_BASE_URL}/chat/completions`, ответ в `choices[0].message.content`). Если формат другой, правьте `src/ai.js`.
