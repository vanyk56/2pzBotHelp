# 2pzBotHelp — бот заявок в клан с ИИ-ассистентом

Discord-бот для приёма заявок в клан 2pz:

- **Кнопка «Подать тикет»** закреплена в канале заявок (`/panel`). Нажатие открывает анкету из 5 полей.
- **Приватный канал заявки** создаётся в категории «заявка в клан, тикеты». Видят его только игрок и модерация.
- **Анкета** уходит в канал с пингом ролей модерации и кнопками «Принять», «Взять на рассмотрение», «Вызвать на обзвон», «Отклонить».
- **ИИ-ассистент** (модель через River API) приветствует игрока, говорит, что в скором времени его вызовут на обзвон, и отвечает на вопросы. Он помнит последние N сообщений тикета и знает анкету игрока.
- **Neon (Postgres)** хранит все заявки и всю переписку. Эти данные пригодятся для дообучения модели.

## Структура

```
config/
  tickets.json         — типы тикетов (клан, коллер, медиа, модератор), их поля и панели. Можно править без кода
  system-prompt.md     — характер, знания о клане и правила ассистента. Можно править без кода
src/
  index.js             — точка входа, подключение к Discord, регистрация команд
  tickets.js           — панель, создание тикетов, кнопки модерации, чат с ассистентом
  streams.js           — автоматические оповещения о стримах Twitch (chotki_mops)
  profiles.js          — профили игроков (Steam ID, Telegram)
  events.js            — сборы на вайп/рейды с RSVP
  assistant.js         — сборка контекста для модели (промпт + анкета + история)
  ai.js                — клиент OpenAI-совместимого API
  db.js                — схема и запросы к Neon
  form.js              — загрузка типов, сборка модалок и проверка ответов
  config.js            — переменные окружения
test/                  — unit-тесты (npm test)
```

## 1. Discord-приложение

1. Откройте [discord.com/developers/applications](https://discord.com/developers/applications) → **New Application**.
2. Вкладка **Bot** → **Reset Token** → скопируйте токен в `DISCORD_TOKEN`.
3. В той же вкладке включите **Message Content Intent**. Без него бот не увидит, что пишет игрок.
4. **OAuth2 → URL Generator**: scope `bot` и `applications.commands`. Права бота:
   - View Channels, Send Messages, Read Message History, Embed Links
   - Manage Channels (создаёт каналы заявок), Manage Messages (закрепляет и удаляет старые панели)
5. Откройте сгенерированную ссылку и добавьте бота на сервер.
6. Роль бота должна стоять **выше** ролей модерации, иначе он не сможет выдать им доступ к каналу заявки.

ID берутся из Discord: **Настройки → Расширенные → Режим разработчика**, затем ПКМ по серверу, каналу, категории или роли → «Копировать ID».

## 2. Neon

1. Создайте проект на [neon.com](https://neon.com).
2. Скопируйте строку подключения (вариант *Pooled connection* тоже подходит) в `DATABASE_URL`.
3. Таблицы создаются сами при первом запуске (`tickets`, `ticket_messages`, `user_profiles`, `stream_alerts`).

## 3. Переменные окружения

```bash
cp .env.example .env
```

Заполните `.env`. Файл не коммитится (есть в `.gitignore`). Токены нигде в репозитории хранить не нужно: на хостинге задайте их как переменные окружения.

| Переменная | Что это |
|---|---|
| `DISCORD_TOKEN` | Токен бота |
| `DATABASE_URL` | Строка подключения Neon |
| `RIVER_API_KEY` | Ключ River API |
| `RIVER_BASE_URL` | По умолчанию `https://api.river.ai/v1` |
| `AI_MODEL` | По умолчанию `zai-org/GLM-5.3-Flash` |
| `AI_CONTEXT_MESSAGES` | Сколько последних сообщений тикета уходит модели как память. По умолчанию 30 |
| `AI_MAX_TOKENS` | Лимит длины ответа. По умолчанию 700 |

## 4. Запуск

```bash
npm install
npm test        # unit-тесты
npm start       # запуск бота
```

Требуется Node.js 22.9 или новее.

После запуска в канале заявок выполните `/panel`. Бот опубликует сообщение с кнопкой, закрепит его и удалит прошлую панель, если она была.

## Команды

- `/panel` — опубликовать и закрепить кнопку подачи (только модерация)
- `/close` — закрыть тикет: статус становится «закрыт», канал удаляется через 10 секунд. История остаётся в Neon (только модерация)
- `/profiles` — список принятых игроков с их Steam ID и Telegram (только модерация, скрытый ответ с пагинацией)
- `/stream add <channel>` — добавить Twitch-канал для оповещений (только модерация)
- `/stream remove <channel>` — убрать Twitch-канал из оповещений (только модерация)
- `/stream list` — список отслеживаемых каналов и текущий канал рассылки
- `/stream set-channel <channel>` — назначить канал Discord для оповещений о стримах (только модерация)
- `/stream remove-channel` — отключить оповещения на сервере (только модерация)
- `/stream test [streamer]` — отправить тестовое оповещение в канал (только модерация)
- `/stream check [streamer]` — проверить статус стримера прямо сейчас

Один игрок может иметь только одну незакрытую заявку. Это ограничение есть и в коде, и в базе (частичный уникальный индекс).

## 5. Деплой на Railway

Бот не слушает HTTP-порт и не нужен публичный домен. Это фоновый процесс (worker).

1. Railway → **New Project** → **Deploy from GitHub repo** → выберите `vanyk56/2pzBotHelp` и ветку `claude/admiring-wright-23xdgi` (или `main` после слияния).
2. Railway прочитает `railway.json`: сборка Railpack, запуск `npm start`, перезапуск при падении (до 10 раз). Node берётся из `engines` в `package.json` (>=22.9).
3. Вкладка **Variables** сервиса: добавьте переменные `DISCORD_TOKEN`, `DATABASE_URL`, `RIVER_API_KEY` (остальные необязательны). ID серверов, каналов и ролей не в Variables, а в `config/servers.json`: заполните его до деплоя, иначе бот не запустится и покажет, какое поле пустое. `.env` на Railway не нужен и не загружается.
4. Для `DATABASE_URL` используйте строку из Neon с `sslmode=require`.
5. Вкладка **Settings → Networking**: публичный домен не создавайте. Если Railway предложит его, отключите.
6. После деплоя откройте **Deployments → Logs**. Должно появиться `Бот ... запущен, команды зарегистрированы на сервере ...`, а таблицы в Neon создаются автоматически.
7. В Discord выполните `/panel` в канале заявок.

Обновления: каждый push в подключённую ветку пересобирает и перезапускает бота. Тикеты при этом не теряются, они лежат в Neon.

Если в логах `Не задана переменная окружения ...`, значит переменная не добавлена в Railway. Если `Disallowed intent(s)`, включите Message Content Intent в Developer Portal. Если `Missing Access` или `Missing Permissions`, проверьте права бота на сервере и его роль.

## Как настроить анкету, стримы и поведение ассистента

- **Оповещения о стримах Twitch.** Бот проверяет статус стримера каждую минуту (по умолчанию `chotki_mops`). Когда начинается стрим, публикуется красивое оповещение в канале `streamChannelId` со ссылкой, превью, игрой и кнопкой перехода. Для теста используйте `/stream-test`.
- **Типы тикетов и анкеты** — `config/tickets.json`. Каждый тип привязан к панели (`main` или `secondary`), у него свои поля, подпись кнопки и префикс канала. Лимит Discord: до 5 полей, подпись до 45 символов. Поле `style: "paragraph"` даёт многострочный ввод. Проверки ответов задаются полями: `numberRange`, `requireDigit`, `requireLink`, `minWords`, `minLength`. После правки перезапустите бота и выполните `/panel`.
- **Серверы.** Настройки каждого Discord-сервера лежат в `config/servers.json`: ID сервера, канал панели, панель (`panelKey`), типы тикетов, категория, роли модерации и голосовой канал. Бот работает на всех серверах из списка, одним токеном. Команды `/panel` и `/close` регистрируются на каждом сервере.
- **Панели.** `/panel`, выполненный на сервере, публикует панель в его `panelChannelId`.
- **Один активный тикет на игрока** на все типы вместе.
- **Анкета клана в два окна.** В Discord в одном окне не больше 5 полей, поэтому клановая анкета из 7 полей идёт в два окна: сначала 5 основных полей, затем кнопка «Далее» со Steam ID (или ссылкой на профиль, или ником) и Telegram (`@username` или `t.me/...`). Ответы первого окна хранятся в памяти 15 минут.
- **Правила картинками** (`/rules`). Публикует публичные и клановые правила картинками в текущем канале или в выбранном параметром `channel`, закрепляет их и заменяет старые. Тексты правил — в `config/rules.json`, картинки рисуются при каждом вызове.
- **Сборы на вайп** (`/event`). Доступны только на серверах с `"events": true` в `servers.json`. Команда принимает название, дату и время по МСК (`12.12.2026`, `12:00`), строку подключения и необязательные клетку карты (`grid`, например `G12`) и роль. Пароль не запрашивается и нигде не выводится. Бот публикует сообщение с блоком данных и кнопками «Буду», «Опаздываю», «Не буду». Кнопка «Проверка» пингует участников выбранной роли, которые ещё не ответили. Ответы сохраняются в таблицах `events` и `event_rsvps` в Neon.
- **Знания и характер ассистента** — `config/system-prompt.md`. Сюда попадают правила клана, требования, FAQ и ограничения. Чем полнее этот файл, тем точнее ответы. Модель получает его целиком при каждом ответе.
- Ассистент видит анкету и статус конкретного игрока, поэтому отвечает по его данным.

## Хранение данных и дообучение

- `tickets` — заявки: игрок, ник, ответы анкеты (JSON), статус, кто принял решение.
- `ticket_messages` — переписка: роль (`user` — игрок, `assistant` — бот, `staff` — модератор, `system` — смена статуса), автор, текст, время.
- `user_profiles` — профили принятых игроков: Discord ID, username, Steam ID / профиль, Telegram, дата принятия и кто принял.
- `stream_alerts` — фиксация отправленных оповещений о стримах, чтобы не дублировать сообщения при перезапуске.

Для будущего дообучения можно выгрузить диалоги из Neon, например:

```sql
SELECT t.id AS ticket_id, t.status, m.role, m.author_name, m.content, m.created_at
FROM ticket_messages m
JOIN tickets t ON t.id = m.ticket_id
ORDER BY t.id, m.id;
```
